订单操作日志同时实时写入 ES + 异步 JSON 日志（ELK 收集）

一、项目结构（新增/修改的文件）
src/main/java/com/example/ordersystem/
├── config/AsyncConfig.java 提供异步线程池
├── entity/OperationLog.java
├── repository/OperationLogElasticsearchRepository.java
├── service/OperationLogService.java 提供一个包装方法，完成实时写ES，并输出纯 JSON 日志（供 Logstash 收集，与实时写入使用完全相同的 docId）
├── aop/OperationLogAspect.java 提供切面方法
└── (原有文件不变)

src/main/resources/
├── application.properties
├── logback-spring.xml
└── (原有文件不变)

根目录/
└── logstash-order.conf   (Logstash 配置文件)，Logstash需要单独启动日志推送！

2.5 启动 Logstash（使用上述配置文件）：
bin/logstash -f logstash-order.conf
2.6 观察 Logstash 输出，应看到相同的文档被再次写入（覆盖，但内容一致）。
2.7 最终一致性验证：无论实时写入和 Logstash 写入谁先谁后，ES 中的文档内容完全相同，且 _id 一致，不会产生重复。

2.8 打开kibana访问(kibana的端口是5601)
- 编辑kibana配置文件中的hosts
vim /usr/local/etc/kibana/kibana.yml
将这一行找到并取消注释即可：elasticsearch.hosts: ["http://localhost:9200"]

- 访问http://localhost:5601/app/management/kibana/indexPatterns
进入Stack Management/Index patterns菜单,配置一个Index patterns(Data View)
Index=order-operations, Timestamp field=operationTime

- 访问http://localhost:5601/app/discover
进入kibana的discover（左边的Analytics菜单下），Change Index Pattern菜单中选择你创建的order-operations*，选择搜索范围，即可进行查询。

- Optional(可选)去Dev Tools 中查看数据情况
进入kibana左下角的Dev Tools的console，输入GET /order-operations/_search命令，能得到和curl命令一样的响应数据。
